## LLM公告证据旁路（v0.6）

- 正式分数恒等于L4规则分。LLM未启用、成功、部分失败、全部失败及异常，不改变分数、排序、推荐等级，也不能否决交易。取消LLM缺失导致的-7分阈值偏移；保留原有市场状态与资金缺失-10分偏移，后者参数外置。
- 输入不提供规则分。`history_win_rate`保留兼容名称，含义为近5根日线收阳比例，同时提供实际样本数；不是相似形态胜率。缺失数据标记“未获取”，不能将默认0、默认板块排名、缺失公告当作真实观测或无风险；展示资金来源、日期、采集时间和实时标记。
- S4固定整批分析时点（Asia/Shanghai），获取近期公告列表及正文摘录。只有明确披露时间且不晚于分析时点的公告进入证据；日期不替代发布时间。正文失败不使用标题冒充原文。数量、摘录长度、HTTP超时、回看范围和并发可配置。
- 输出事件、影响对象、fact/rumor/inference标注、原文引用、信号冲突及未知项，不生成交易分数、买卖指令或置信度。事件证据编号必须存在，引用优先逐字匹配；仅空白/换行差异允许忽略，数字、单位、文字、标点、大小写及字符顺序不可变化，不做模糊或语义匹配。不合格事件移至待核实，不修补残缺JSON。
- 保留模型原始quote及原始公告，不改写正文；通过的事件附quote_match_mode=exact/whitespace_only，报告区分逐字匹配和仅忽略空白匹配。引用匹配不认证整段事件解释。
- 提示词仅允许将同一对象、同一口径、可比较时段的实际矛盾列为冲突。计划价格上限高于实际执行价属于正常约束关系，不因差值大而列冲突；无证据时conflicts为空，缺失数据写unknowns。已知年度/期间须在摘要、事件、未知项中保持一致，不把已知“2026年度”表述为期限完全未知。
- 来源及引用匹配不是独立事实核验；模型摘要和冲突解释也可能出错，均标注待复核。保留S3既有公告关键词规则，本次不改变其硬过滤标准；LLM不反向写入规则风险标志。
- S4规则分、排名和等级生成后立即回调发布、入库；不获取旁路公告、不等待模型。正式运行状态可为completed，同时旁路仍为pending/running。规则就绪后的报告异常亦不撤销已发布推荐。补充阶段不得重排、改级、重复推荐或创建模拟交易。
- 旁路使用冻结的全部Top30副本（含skip），后台补充独立`.llm.md`和同名`.llm.json`，原始规则报告链接至补充文件。Web详情独立显示旁路状态与结果；失败显示未评估。正式推荐及历史LLM评分列保持兼容，不改旧列。
- 新增pipeline_sidecars表：run_id主键、generation、run_started_at、status、deadline_at、finished_at、results_json。状态为pending/running/completed/partial/timed_out/failed/disabled；按批次token及数据库当前启动时间拒绝旧结果。启动时create_all只新增独立表，不改旧推荐表。
- 正式推荐、对应模拟交易和completed状态在同一事务提交；失败全部回滚。旁路初始化/启动为独立事务，失败回滚旁路session并记录未评估，不撤销正式发布。正式保存、进度和收尾在写入SQL中匹配启动时间；重跑先条件UPDATE认领写锁，再同事务清除旧结果，阻止检查后重跑的竞态。
- LLM_BATCH_TIMEOUT默认30秒，整批共享，包含发布后等待后台启动、排队、限流锁/时隙、公告和模型。公告HTTP在spawn独立进程执行，父进程在整批截止时终止并回收请求进程，再释放共享门控；子进程启动后也检查剩余预算，不因慢速响应头/正文持续续期。未带截止的既有请求保留共享Session。模型请求/重试继续取剩余预算，协调器到期返回完成项，其余未评估；迟到结果不采纳。
- GET /pipeline/status/{id}新增run_generation及sidecar状态/结果。可选generation与当前批次不一致时重置日志游标；前端清空旧批次显示。正式完成后继续轮询旁路，直到其终态。进程重启不恢复内存任务，截止后显示未评估，不伪装成功。
- CLI先输出规则报告路径，再保持进程等待有截止的后台补充；定时与手动Web入口共用提前发布回调。公告覆盖有限、摘录可能截断，不能据此判断无其他风险。
- DeepSeek默认LLM_THINKING_ENABLED=false，以extra_body传入thinking.type=disabled；其他提供商不下发该专用参数。LLM_MAX_RETRIES默认0，SDK隐藏重试关闭，失败标为未评估；显式启用重试可能放大耗时。
- 单次模型请求以LLM_TIMEOUT=30秒验收，不等于整批S4含公告获取/排队30秒。精简摘要重复数字、重复事件和长法规引文，但保留关键事实、期限、审批阶段、证据和必要未知项；不靠降低输出预算或放宽引用校验提速。

整批截止与提前发布验收详见[发布隔离专项](llm-sidecar-publication.md)。下方保留v0.1进度功能规格。

## 问题与目标

目前后台持续运行，但页面直到全程结束才显示阶段数量，日志在pipeline.run前后存在长时间空白，用户无法区分正常轮询与停止推进。

- S0至S4每个阶段结束立即提交输出数量；尚未结束显示“–”，已结束但0只显示0。
- 定时、手动执行共用阶段进度及业务日志捕获。预加载、数据获取、阶段切换、轮询和降级等主执行线程INFO及以上日志实时保存；后台采集线程的逐股日志不逐条转发。
- 仪表盘最近记录定期刷新，不需用户刷新；日期链接至执行详情。
- 详情页显示阶段数量、实际市场状态、结束时间、日志总数及最后进展时间；追加日志保留历史，用户向上阅读时不强制跳至末尾。
- 显示页面连接状态；连接中断保留已显示内容并重连。“已连接”只表示查询接口可达，不等同于选股线程一定正常。
- 执行失败保留已完成阶段和历史日志。运行中刷新页面可恢复已有记录；结束后补齐日志分页再停止刷新。
- 未改动策略阈值、交易决策、TDX重试、HTTP降级或调度时间。

## 接口及配置

复用PipelineRun.stages_json与PipelineLog，不增加数据库字段或迁移。

- GET /api/recent-runs：最近5次运行的id、日期、状态、实际市场状态及已完成阶段数量。
- GET /pipeline/status/{id}?after={log_id}：运行状态、已完成阶段、增量日志、下一游标、日志总数和最后日志时间；非法游标400，不存在404，不缓存响应。
- WEB_PIPELINE_POLL_SECONDS：页面轮询间隔，默认3秒。
- WEB_PIPELINE_LOG_PAGE_SIZE：单次增量日志最大条数，默认200。含义同步.env.example。

阶段进度在阶段完成后提交；页面最多等待一次轮询间隔再显示。不承诺每只股票级别的进度或任务存活检测。
