## 问题与目标

此前虽然LLM不参与打分，但S4仍同步等待全部公告和模型请求。默认30只、每只3条正文，加上公告列表共120次HTTP；全局串行门控意味着请求序列至少约119秒（未计网络和抖动）。旧批次上限按数量放大到255秒，会拖延正式报告和推荐入库。单模型约5秒的验收不能证明整批及时发布。

本次将正式发布与旁路彻底拆开：规则评分后立即发布入库，随后后台补充。未运行真实选股、交易、模拟交易管线或外部LLM；验收仅使用mock、临时SQLite和本地HTTP服务器。

## 实施前验收用例

1. S4规则结果已就绪而LLM阻塞时，推荐页可查询完整记录；正式运行可为completed，旁路仍pending/running。
2. 旁路成功、单股失败、整批异常、整批超时均不改变正式分数/排名/等级，也不重复推荐或模拟交易。
3. 30只候选共享同一整批截止，不随数量扩大。包含排队、限流锁/时隙、公告HTTP和模型；截止后不再安排外部请求。
4. 截止返回已完成结果，其余未评估；在途任务的迟到返回不能写回，正式上下文不受工作线程修改。
5. 同日重跑的旧token、旧启动时间及旧ORM缓存不能覆盖新记录；旧日志游标重置，旧旁路内容隐藏。
6. 定时、手动、CLI均先发布；CLI输出路径后再等待后台，Web正式结束后继续观察旁路。
7. 旧数据库仅新增旁路表，不修改历史正式记录；旁路任务进程重启后不伪造恢复成功。

最初8项新增用例在旧实现下失败。新增测试覆盖范围随后补充到19项，包括完整30只后台、限流与旧库兼容等。

## 实现与发布顺序

1. `_run_stage4`仅规则评分、排序及冻结Top30，不获取旁路公告，也不调用模型。
2. `on_rules_ready`立即保存正式推荐；既有保存入口幂等，重入不改变已有推荐，模拟交易的创建保留原有规则且不重复。正式推荐、模拟交易、完成状态和完成时间单事务提交，任一正式写入失败全部回滚。旁路初始化与启动使用后续独立事务，失败回滚并保留已提交的正式结果。
3. 提交后立即启动后台线程，不等待市场概况或最终Markdown生成，避免这些后处理消耗全部旁路预算。后台使用冻结副本，不调用merge_and_rank或正式保存函数。
4. 正式报告保留规则快照，链接到独立`.llm.md`和`.llm.json`补充。Web旁路文件使用独立时间/UUID基名，避免旧后台任务覆盖新批次；初始规则审计与后台审计分开保存。CLI已有正式文件时可使用同基名补充。
5. 后台仅更新独立旁路表及补充日志、文件。规则发布后的报告错误或后台异常不撤销已发布推荐。

## 整批截止

新增`LLM_BATCH_TIMEOUT=30`，含义写入.env.example及配置指南。Web在规则发布后确定单调时钟截止及可持久化的deadline_at；不是30只各等30秒，也不是给每一轮重置预算。

- Runner接收整批绝对截止，固定数量线程；排队任务执行前检查截止，到期取消尚未开始的future。
- 公告获取把截止传入`em_get`。锁使用有时限acquire，限流时隙无法在预算内到达就退出；带截止的HTTP在spawn独立进程执行，请求取配置超时与剩余预算的较小值，父进程到期终止并join回收后才释放共享门控。子进程启动后再次检查截止，不启动迟到请求。
- 模型请求也取剩余预算；客户端可选重试/退避受同一剩余预算约束，默认仍零重试、SDK无隐藏重试。
- 协调器截止时收集已完成项，其余标未评估；不接纳迟到分析结果。少量线程调度/本地保存开销可能使返回时间略超测试预算，不是实时操作系统硬中断。
- Python不能强杀已运行线程；公告请求通过独立进程终止释放socket，不依赖requests读取超时。模型SDK调用仍以剩余超时退出，不占东财共享门控，协调器不采纳迟到结果。此方案不靠放宽全局限流提高吞吐。
- 独立进程只用于带截止的公告HTTP，父进程继续维持原串行门控；无截止的旧调用保持共享Session/Keep-Alive。旁路每次请求新增进程启动开销且不跨请求复用连接，可能降低30秒内的证据覆盖率；不新增第三方依赖，不为提高覆盖率放宽截止。进程创建/回收有少量调度开销，不能承诺操作系统实时硬截止。

完整分析覆盖率和及时发布分开评价。若30秒不足以分析完30只，会明确显示部分完成/未评估，不能把缺失当无风险。

## 存储、状态与同日重跑

新增`pipeline_sidecars`表：run_id主键/FK、generation、run_started_at、status、deadline_at、finished_at、results_json。应用原有init_db/create_all自动补建独立表；旧DailyRecommendation和SimulatedTrade表不改列，不回写历史分数。

正式run.status=completed表示规则事务发布完毕。旁路状态独立为pending、running、completed、partial、timed_out、failed或disabled。后台完成通过token及数据库当前started_at的SQL条件更新；不依赖旧线程缓存的ORM对象。正式保存先执行含started_at条件的UPDATE获取数据库写锁，再在同事务保存推荐/模拟交易/完成状态；阶段进度与成功/失败收尾也把批次条件写在UPDATE中。重跑先用旧启动时间/状态条件UPDATE认领写锁，然后同事务清除旧结果。即使旧任务先检查为当前、随后发生重跑，其下一次条件写入仍被拒绝；若旧保存已持有写锁，重跑等提交后再清除，不在半批数据中穿插。

`GET /pipeline/status/{id}`新增run_generation和sidecar对象，旁路结果响应只投影研究字段，不回传庞大原始提示词。可选generation不匹配时重置after游标；前端清空旧日志/旧旁路内容，所有文本用textContent显示。正式结束后仍继续轮询pending/running旁路，终态后补齐日志再停止。截止后只额外观察一个已有页面轮询周期，收齐本地终态提交，不延长模型/HTTP预算，也不无限轮询重启前遗留任务。

任务为进程内后台，不是持久队列。进程重启后不会自动重放外部请求；若仍是pending/running且超过deadline，API显示超时和未评估，保留正式结果。

## 首轮离线验收结果（2026-10-30）

| 场景 | 测试预算与观测 | 结论 |
|------|----------------|------|
| 30条正式推荐先保存，模型被Event阻塞 | 规则发布约0.047秒；后台预算1秒 | 返回时30条推荐及30条临时模拟交易已存在；后台终态不改数量、分数和等级 |
| 30只排队，首只模型不遵守超时 | 测试预算0.08秒，约0.094秒返回 | 仅首只发起模型调用，30只均有终态；释放迟到返回后结果不变 |
| 30只、各3公告、真实门控逻辑+模拟HTTP | 测试预算0.12秒，约0.125秒返回，启动19次请求 | 未走完原120请求，截止后无新增请求，30只均返回完成/未评估记录 |
| 单股异常 | 30只中指定1只抛错 | 29只正常，不取消其他标的 |
| 整批异常 | Runner抛错 | 30只均未评估，正式快照不变，仅一个补充任务 |
| 发布后报告错误 | 已提交正式结果后抛错 | 正式状态及记录保留，不报告为选股失败 |
| 同日重跑 | 旧token、旧started_at、旧ORM缓存、旧游标 | 不写回旧正式或旁路结果，不混入新日志 |
| 旧SQLite文件 | 预建旧pipeline_runs及历史行后启动应用 | 自动新增旁路表，历史正式状态保留 |
| CLI | 模拟入口及线程join | 先打印正式报告路径，再等待后台 |

以上是缩短预算的离线调度/隔离测试，不是生产网络30只压力运行。原始指标在`tmp/sidecar-final-acceptance.xml`。当时全量321项通过，随后diff审核发现下述三个边界阻塞，不能以首轮通过替代修复验收。

## 三个P1修复及验收（2026-10-31）

实施前用例：旁路表INSERT/UPDATE/running写入与线程启动失败不撤销正式发布；正式交易写入失败不留半批；重跑在读与写之间发生时拒绝旧保存、进度及成功/失败收尾；正式保存事务持锁时重跑等待，旧重跑请求不能清理新结果；慢速响应头/正文不能续期，截止后socket关闭、子进程回收、共享门控释放；子进程启动过晚不得发送请求；正常HTTP的JSON、参数、状态码与raise_for_status保持兼容。

首批11项在旧实现下9失败、2通过；随后补齐到15项正式回归用例。原始失败记录保留在`tmp/p1-before.xml`，修复后的全量回归和耗时指标保留在`tmp/p1-final-regression.xml`。

| 场景 | 验收结论 |
|------|----------|
| 旁路INSERT/UPDATE/running与线程启动故障 | 正式推荐/模拟交易及completed已提交，返回无正式error，session可继续查询；旁路独立失败，不无限重试 |
| 正式模拟交易INSERT故障 | 推荐、模拟交易、完成状态全部回滚，未留下部分正式记录 |
| 检查后重跑 | 保存、进度、成功/失败收尾的批次条件UPDATE均拒绝旧写入 |
| 正式事务与重跑交错 | 重跑等待写锁，提交后清除完整旧记录；旧重跑请求不删除新批次推荐 |
| 本地HTTP慢速响应头/正文 | 1.5秒整批预算，到期终止子进程，socket断开，无遗留子进程/门控锁；后续正式门控调用立即通过 |
| 子进程启动截止与正常响应 | 过期不发送请求；JSON、查询参数、HTTP错误语义兼容 |
| 固定调度交易日 | 测试使用2026-10-30，不依赖执行当天是否为周末 |

最终全量**336项通过**（33.111秒），包含15项本次新增用例及原30只候选/旧库兼容回归；Python/JavaScript语法与`git diff --check`通过。1.5秒预算的慢速响应头/正文分别于1.516/1.500秒完成终止和回收，确认服务端socket断开、无活跃遗留子进程、门控已释放；正常本地HTTP连同spawn耗时0.578秒。上述均为本地样本，不代表生产网络耗时或30只完整分析覆盖率。

修复后再次diff审核重点：正式保存中不再分次commit，旁路写库和启动异常均回滚且不抛向正式发布；公告截止分支在finally中终止/join回收进程再释放锁；保存/进度/成功和失败收尾的条件在写入SQL中，重跑先认领写锁再清理；旧正式表无列变更，create_all补建独立旁路表的旧库测试仍通过。本地覆盖范围内未发现新增P1阻塞。
