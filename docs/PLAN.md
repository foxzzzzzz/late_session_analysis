# 运行进度可视化实施计划

本计划对应[增量规格](PRD.md)，复用现有Flask、SQLite、StageTracker和原生JavaScript，无新增运行依赖。

## Phase 1：进度持久化与业务日志

- StageTracker结束事件提供已完成阶段数量，PipelineService捕获当前执行线程的业务日志。
- 定时与手动入口绑定run_id，阶段结束提交进度；失败保持已有阶段数据。
- 验收：模拟管线在S0后尚未结束时，另一个请求可读取数量和日志；中途失败仍保留S0；不串入其他线程日志；退出后移除临时日志处理器。
- 状态：已通过对应测试。

## Phase 2：页面自动更新

- 新增增量日志及最近运行查询，页面轮询更新数量、状态和日志。
- 正文以textContent插入，初始模板转义；游标防止重复，结束后补齐日志分页。
- 验收：0与未结束正确区分、错误游标/缺失运行正确响应、详情脚本加载、模板消息转义。
- 状态：接口和模板测试通过；JavaScript语法检查通过。

## Phase 3：合并回归与云端验收

- 本地Web、进度及相关管线共57项测试通过，无需调用行情、LLM或交易接口。
- 云端同步并重启后，以正常定时执行或用户主动选择的测试任务验收：保持仪表盘与详情页打开，确认阶段结束后约3秒内更新；中途刷新详情能恢复日志；结束后日志完整且数量与最终结果相同。
- 云端实际浏览器及定时执行验收待完成。本次没有向云服务器执行命令，也没有启动真实选股或模拟交易。
