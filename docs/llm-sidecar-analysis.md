## 问题与设计结论

原设计把模型自评置信度映射为20%～40%交易评分权重，且批次有任何LLM成功就取消全体的-7分阈值补偿。两种分数未经收益校准，调用可用性会改变交易标准；现有回测只走规则路径，不能证明融合有效。

当前正式决策只使用规则。保留资金缺失的原有-10分调整，不在本次重新设计资金评分。公告关键词硬过滤仍是S3规则，旁路模型既不控制它，也无权扣分、加分、调整阈值或否决。

## 实施前测试用例

1. 固定候选池，对比未启用、全部成功、部分失败、全部失败、调用异常、极端分数及风险判断，正式分数/排名/等级完全一致。
2. 阈值仅依赖市场状态与资金可用性；LLM状态不参与。
3. 默认缺失与真实0区分；收阳率包含实际样本数，不称相似形态胜率；资金来源/日期/采集时间可见，隐藏规则分。
4. 仅接纳分析时点之前且回看范围内、有明确发布时间的正文；时间不明确/未来公告排除；原文获取失败记录未知，数量上限覆盖失败请求。
5. 模型按事件、对象、事实/传闻/推断、引用、冲突、未知项输出；伪造ID/不匹配引用移至未知，不修补截断JSON。
6. 报告包含skip标的旁路结果，失败显示未评估；JSON审计保存证据及输入；Web日志和旧数据库存储不恢复LLM评分。

## 数据与处理链

`L4规则评分 → 固定正式分数/阈值 → 先发布/入库 → 后台公告列表+正文 → LLM旁路JSON → 引用校验 → 独立补充表/报告/审计JSON`

- 公告来自东方财富公告列表`np-anotice-stock.eastmoney.com/api/security/ann`，正文来自`np-cnotice-stock.eastmoney.com/api/content/ann`。通过既有HTTP门控。
- 使用列表`display_time`（含毫秒），不用仅有日期的`notice_date`推定盘中可见。记录正文来源链接、附件链接、发布时间、摘录及截断标志；不进行PDF解析。
- 单批固定Asia/Shanghai分析时点；正文最多取配置长度，默认只尝试3条。空列表不能区分无公告与获取失败，统一表达为证据不可用；所有结果都提示检索覆盖有限。
- 事件的`classification`由模型解释，不是系统认证。`quote_matched=true`说明原样引用或忽略空白后可在摘录中找到，具体由`quote_match_mode=exact/whitespace_only`标明；数字、文字、标点等非空白变化一律不采信，不做大小写/全半角转换、数字重写或模糊匹配。原始quote和正文保持不变；事件所述影响、传闻真伪及是否已实施仍需核实。摘要和conflicts始终是模型待复核解释。
- 模型输出旧格式buy/score或残缺JSON均视为未评估。当前客户端LLM_MAX_RETRIES默认0，SDK隐藏重试关闭；S4也不对失败标的整批再重试，避免旁路任务重复拖延。可显式启用客户端重试，但可能超过单次超时。

## 配置与兼容
